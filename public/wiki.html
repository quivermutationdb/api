A quiver here is a finite directed multigraph with no loops or 2-cycles, encoded by a skew-symmetric integer exchange matrix B = (bij): bij > 0 means bij arrows from i to j, and bji = −bij. Every record in the database is one isomorphism class of such a quiver, or one mutation class of them. Quivers here are always connected. For what is currently covered, see the live table on the About page.

Quiver / exchange matrix

An unlabeled quiver is a skew-symmetric integer matrix up to simultaneous permutation of its rows and columns (relabeling the vertices). The entry bij records the signed number of arrows between vertices i and j: bij = 3 means three arrows i → j, and bij = −3 means three arrows j → i. Skew-symmetry (bji = −bij, zero diagonal) is exactly the statement that the quiver has no loops and no 2-cycles. Quivers and their mutation are the combinatorial engine of cluster algebras [FZ02].

The Matrix column on Browse and each quiver page shows this exchange matrix, row-major. In storage it is kept compactly as its strictly-upper-triangular entries, which determine the rest.

Rank

The number of vertices, i.e. the size n of the n×n exchange matrix. Mutation never changes the rank, so it is shared by every quiver in a mutation class.

Mutation

Mutation at a vertex k is the fundamental operation of cluster theory [FZ02]. It produces a new quiver B′ from B by the skew-symmetric mutation rule:

b′ij = −bij   if i = k or j = k,
b′ij = bij + ( |bik|·bkj + bik·|bkj| ) / 2   otherwise.

The added term is bikbkj when both bik and bkj are positive, −bikbkj when both are negative, and 0 when they have opposite signs — so arrows are only created along paths i → k → j. Mutation is an involution: mutating twice at the same vertex returns the original quiver.

def mutate(matrix, k):
    n = len(matrix)
    rows = [list(row) for row in matrix]
    for i in range(n):
        for j in range(n):
            if i == k or j == k:
                rows[i][j] = -matrix[i][j]
            else:
                b_ik, b_kj = matrix[i][k], matrix[k][j]
                rows[i][j] = (matrix[i][j]
                    + (abs(b_ik) * b_kj + b_ik * abs(b_kj)) // 2)
    return tuple(tuple(r) for r in rows)

Canonical form & quiver ID

Two matrices that differ only by a relabeling of the vertices are the same unlabeled quiver. To give each isomorphism class a single stable identifier, we compute a canonical form — the unique representative of the class — and hash it. The canonical form is defined as the lexicographically smallest matrix in row-major order over all n! relabelings. That is a mathematical definition, not an implementation detail: the identifier never depends on which software or libraries happened to be installed. It is computed exactly by a branch-and-bound search (with pruning over interchangeable vertices).

The ID is Q.n{rank}.{sha256[:16]}; a mutation class is MC.n{rank}.{…}. If you have a matrix rather than an ID, in any labeling, the Search page and /api/lookup will canonicalise it and take you to the right quiver.

def quiver_id(matrix):
    canon = canonical_form(matrix)           # lex-min over all relabelings
    blob = json.dumps(to_lists(canon), separators=(',', ':'))
    return "Q.n%d.%s" % (len(canon), sha256(blob)[:16])

Labeled, distinct, canonical

A mutation class can be counted three ways, and the site keeps them apart:

  • Distinct quivers — the isomorphism classes in the mutation class, each quiver ID once. This is what class exploration works with, and what distinct_quiver_count counts.
  • Labeled matrices — every labeled exchange matrix reachable by mutation; the same unlabeled quiver appears once per vertex labeling. Counted by class_size, and stored only for small finite classes (see class sizes).
  • Canonical representative — the single distinct quiver whose matrix is lexicographically minimal over the whole class; the class ID is its hash.

The gap between the first two is large: the E8 mutation class has 1,574 distinct quivers but tens of millions of labeled matrices. Class exploration is therefore done over unlabeled quivers — every mutation result is canonicalised before it is recorded. Because mutation commutes with relabeling, the set of quivers reached, the class membership, and the class ID are exactly the same as they would be from a labeled search.

def canonical_class_rep(members):        # members are canonical forms
    return min(members, key=lex_key)     # lex-min over the whole class

Census & cells

QMD is a census, not a sample of the literature. A cell (n, h) is the set of all connected quivers on n vertices with every |bij| ≤ h, and for each cell listed on the About page the database contains every member. The number of quivers in a cell is known independently, by a Burnside/Pólya count over the symmetric group [HP73] corrected to connected quivers, and the generated total is checked against it — they have agreed exactly at every rank generated so far. /api/stats reports both as distinct_quivers and census_size; equality means the cell is complete.

Cells grow fast — there are over 8·1052 quivers on 10 vertices with |bij| ≤ 10 — so beyond the enumerable cells the database holds documented samples, and generator on /api/stats says which a rank is (orderly = complete census, sample:N = N drawn quivers). A sample is drawn uniformly from labeled matrices of the cell, which is not uniform over isomorphism classes: quivers with large symmetry groups are under-represented.

Weight bound vs exploration bound

Two different bounds are at work, and confusing them is the easiest mistake to make with this data.

  • The cell weight bound h says which quivers are in the census: |bij| ≤ h. It varies by rank and is reported per rank as bound.
  • The exploration bound is always 2. Mutation is followed only while every entry stays within |bij| ≤ 2; a mutation that would reach 3 stops that branch. This is not an arbitrary window: for a connected quiver of rank ≥ 3, reaching an entry of 3 already proves the class infinite (Derksen–Owen), so there is nothing to gain by continuing.

A quiver may therefore have max edge weight 7 (inside a cell with h = 10) while its class was never explored at all — it was settled by the criterion below.

Orderly generation

A cell is enumerated by canonical augmentation (orderly generation): quivers are grown one vertex at a time, and at each level only the canonical representative of each isomorphism class is kept, so every quiver is produced exactly once without ever listing the astronomically many labelings. Generation uses a second, hereditary canonical form — the lexicographically least sequence of strictly-lower-triangular rows — because that form restricted to a leading block is again canonical, which the row-major ID form is not. The two forms are used for different jobs: the hereditary one drives generation, the row-major one defines identifiers.

Derksen–Owen criterion

A connected quiver on at least three vertices with some |bij| ≥ 3 has infinite mutation type [DO08, Cor. 8] (which rests on the classification of 3-vertex mutation classes [ABBS08]). Connectedness and rank ≥ 3 are both needed: the rank-2 quiver with three arrows has a mutation class of size 2, and remains finite if isolated vertices are added.

The database uses this in two places. A quiver that already contains an entry ≥ 3 is recorded as mutation-infinite with no exploration at all (see explored vs unexplored) — at rank 4 with h = 10 that settles over 99.9% of the cell. And an exploration that reaches an entry of 3 proves the class it was exploring infinite.

Exploration state

Every explored mutation class records how far its breadth-first search got, as exploration:

  • complete — the search drained: no unexplored quiver remains and no mutation left the exploration bound. The class is finite and fully known.
  • bound — some mutation reached an entry of 3. For rank ≥ 3 this proves the class mutation-infinite; what is stored is the part explored within the bound.
  • truncated — the node cap stopped the search before either of the above. Finiteness is unknown: no Dynkin label, no exact size, no definite "no" for any semidecidable property.

Node cap

An infinite mutation class never ends, so every exploration carries a cap on the number of distinct quivers it may visit; the value used for a rank is reported as node_cap. A finite class smaller than the cap is unaffected — it drains first. Reaching the cap makes a class truncated unless the exploration bound was already crossed, in which case the class is infinite regardless and the cap only limits how much of it is kept.

Explored vs unexplored

Not every quiver has a stored mutation class. A quiver settled by the Derksen–Owen criterion carries a finiteness verdict with no class row: explored: false, mc_id: null, mutation_finite: false. Browse and Search show these as Infinite rather than as a class, and the explored filter selects either kind.

Per-quiver mutation_finite is three-state and is the field to trust for a single quiver: true if its class was explored to exhaustion, false if the class crossed the bound or the quiver itself satisfies the Derksen–Owen criterion, and null if neither was established. Note that is_open is a class-level flag and is reported as false for a quiver with no class row — do not read it as "finite"; read mutation_finite.

Acyclic

The quiver has no directed cycle (drawing an edge i → j whenever bij > 0). Acyclic quivers are the well-understood base case of cluster theory: the path algebra kQ is finite-dimensional and its representation type is defined. Computed by an iterative depth-first three-colouring — a back-edge to a vertex still on the stack (GRAY) witnesses a cycle.

def is_acyclic(matrix):
    n = len(matrix)
    adj = {i: [j for j in range(n) if matrix[i][j] > 0] for i in range(n)}
    WHITE, GRAY, BLACK = 0, 1, 2
    color = [WHITE] * n
    for start in range(n):
        if color[start] != WHITE:
            continue
        stack = [(start, 0)]; color[start] = GRAY
        while stack:
            u, idx = stack[-1]
            if idx < len(adj[u]):
                stack[-1] = (u, idx + 1); v = adj[u][idx]
                if color[v] == GRAY:   return False     # back-edge => cycle
                if color[v] == WHITE:  color[v] = GRAY; stack.append((v, 0))
            else:
                color[u] = BLACK; stack.pop()
    return True

Connected

The underlying undirected graph — an edge wherever bij ≠ 0 — is connected. A single-vertex quiver is connected by convention.

Every quiver in QMD is connected. A disconnected quiver is a disjoint union of smaller ones and its mutation class is the product of theirs, so the census stores the components instead. The field is_connected is still present in the API and exports (it is always true), but there is nothing to filter on, so Browse and Search do not offer it. Connectedness also matters mathematically here: the Derksen–Owen criterion is false without it.

Max edge weight

The largest |bij| in the quiver — the heaviest single arrow-bundle. A quiver is simply-laced exactly when its max edge weight is ≤ 1, which is what the is_simply_laced filter selects. Do not confuse this per-quiver value with the cell weight bound h, which is a property of the census.

def max_edge(matrix):
    return max(abs(matrix[i][j])
               for i in range(len(matrix)) for j in range(len(matrix)))

Bipartite

Every vertex is a pure source or a pure sink — no vertex has both an incoming and an outgoing arrow. Equivalently, the vertices two-colour so that every arrow runs from the first colour class to the second. This is stronger than bipartiteness of the underlying graph, which ignores directions.

def is_bipartite(m):
    n = len(m)
    for i in range(n):
        has_out = any(m[i][j] > 0 for j in range(n))
        has_in  = any(m[i][j] < 0 for j in range(n))
        if has_out and has_in:
            return False
    return True

Abundant

Every pair of distinct vertices is joined by at least two arrows: |bij| ≥ 2 for all i ≠ j [War14, FN24] (the same property is called 2-complete in [FT18]). An abundant quiver is automatically connected, and QMD requires at least two vertices. The Markov quiver is the smallest abundant quiver.

def is_abundant(m):
    n = len(m)
    if n < 2: return False
    return all(abs(m[i][j]) >= 2
               for i in range(n) for j in range(i + 1, n))

Planar

The underlying multigraph can be drawn in the plane without crossing edges. Every graph on at most 4 vertices is planar (the obstructions K₅ and K₃,₃ need 5 or more vertices), so the value is true for every rank ≤ 4 quiver. For rank ≥ 5 it is reported as unknown (null) until a full planarity test is wired in — it is never guessed.

Representation type

For a connected acyclic quiver Q over an algebraically closed field, the path algebra kQ has a representation type — finite, tame, or wild — governing how complicated its indecomposable representations are. Finite type holds exactly for the simply-laced Dynkin diagrams (Gabriel's theorem [Gab72]), and tame type exactly for the Euclidean (extended Dynkin) diagrams [Naz73, DF73]. Equivalently it is read off the symmetric Tits form M = 2I − |B| [ASS06]: positive definite ⟹ finite, positive semidefinite (not definite) ⟹ tame, indefinite ⟹ wild.

Reported as unknown (null) when Q is not acyclic, since kQ is then infinite-dimensional and the trichotomy does not apply. The minors are computed with exact integer determinants, so the classification is exact.

def representation_type(m):
    if not is_acyclic(m):
        return None                                   # kQ infinite-dimensional
    n = len(m)
    M = [[2 if i == j else -abs(m[i][j]) for j in range(n)] for i in range(n)]
    if positive_definite(M):       return "finite"    # Dynkin
    if positive_semidefinite(M):   return "tame"      # Euclidean
    return "wild"                                      # indefinite

Symmetry group

The automorphism group of the quiver: all vertex permutations σ with bσ(i)σ(j) = bij. It is computed for the quiver's canonical form, so it is an invariant of the isomorphism class. Reported as its order, a name for small familiar groups (e.g. Z/2, S₃) and a generating set; the generators are one convenient choice, not a canonical one, and the name falls back to the order for groups the small-order table does not cover. Computed by brute force over all n! permutations, which is exact.

def symmetry_group(m):
    n = len(m)
    elements = [p for p in permutations(range(n))
                if all(m[p[i]][p[j]] == m[i][j]
                       for i in range(n) for j in range(n))]
    return {"order": len(elements), "name": group_name(elements), ...}

Labeling count

How many labeled matrices of the class map to this one unlabeled quiver (labeling_count). It is n! divided by the order of the symmetry group, and it is recorded only when the class's labeled orbit was computed — otherwise it is null. Class member lists are ordered by it, most-labeled first, after the canonical representative.

Mutation class

The mutation class of a quiver is the set of all quivers reachable from it by any sequence of mutations. It is the natural equivalence class in cluster theory: mutation-class invariants (Dynkin type, mutation-finiteness, the acyclicity conditions) are shared by every member.

What is stored is the explored part. For a complete class that is the whole class; for a bound or truncated class it is the subset the bounded search reached, and the class ID is the lex-minimum over that subset. Classes are built by breadth-first search from each quiver of the cell, with searches that share a quiver glued together (union-find).

Class sizes

Three counts, deliberately kept distinct:

  • distinct_quiver_count — the number of distinct quivers explored in the class. Always present.
  • class_size (also served as labeled_size and size_of_explored_mutation_class) — the number of labeled matrices. Present only when the labeled orbit was computed, which is done for complete classes small enough to hold one (the test is distinct × n! ≤ 200,000, a safe upper bound on the orbit); otherwise null, with labelings_stored: false on the class page and the API.
  • The explored frontier, below.

A null class size therefore means "not stored", not "infinite" — read mutation-finiteness for that.

Merged orbit count

How many separate breadth-first searches were glued into this class (merged_orbit_count; 1 means none). Two searches that reach a common quiver are exploring the same class. For a complete class this can only ever be 1 — a finite class is drained from any of its members — so a value above 1 always belongs to a partially explored class.

Explored frontier

The number of explored quivers that have a mutation leaving the exploration bound — the boundary of what was enumerated (size_of_explored_frontier). It measures how much of an infinite class the bounded search saw. Only the count is stored, not the matrices themselves. For a class glued from several searches the counts are summed, so a quiver on the boundary of two of them is counted twice.

Dynkin type

Cluster algebras with finitely many cluster variables are classified by Cartan–Killing types [FZ03]; in the skew-symmetric case this says a class has finite cluster type exactly when it is mutation-equivalent to an orientation of a simply-laced Dynkin diagram. The label recorded here is that type: An, Dn, E₆, E₇ or E₈, or a sum such as "A1 + A2" for a class whose canonical representative is disconnected. Only A/D/E occur — the multiply-laced types B, C, F, G need skew-symmetrizable matrices, which are not in the database yet.

Computed by matching each connected component of the class's canonical representative against a reference table of Dynkin quivers up to rank 8, by mutation-class identity, so it is exact rather than a heuristic. It is null for classes that are not of finite type, and also for classes whose exploration was not complete — an unfinished search cannot certify a type.

Mutation-finite

A class is mutation-finite if its mutation class is a finite set, and mutation-infinite otherwise. The skew-symmetric mutation-finite quivers are classified [FeShT12]: rank 2, quivers arising from triangulated surfaces [FST08], or one of 11 exceptional mutation classes (two of which were found in [DO08]). Note that mutation-finite is weaker than finite cluster type: every class with a Dynkin type is mutation-finite, but so are the affine and surface classes, which have no Dynkin label.

The database records the verdict in three mutually exclusive flags, and class pages render them as:

  • Mutation-finite (proved) — is_finite_confirmed: the class was explored to exhaustion.
  • Mutation-infinite (proved) — is_infinite_confirmed: a mutation reached an entry of 3 at rank ≥ 3 (Derksen–Owen).
  • Unknown — all three flags null: the search was truncated. (is_infinite_expected is reserved for a future evidence-based state and is not currently emitted by the pipeline.)

Filtering on is_mutation_finite uses the proved flags only: a class whose finiteness is unknown matches neither true nor false.

Local acyclicity

A cluster algebra is locally acyclic if it admits a cover by finitely many acyclic cluster algebras, in the sense of Muller [Mul13]. Locally acyclic cluster algebras inherit much of the good behaviour of acyclic ones — they are finitely generated, integrally closed, and equal to their upper cluster algebra. Deciding it is hard in general, so QMD records sufficient combinatorial conditions (Banff, Louise) rather than the property itself.

Both conditions are built on covering pairs: an arrow between two vertices such that deleting either one leaves a quiver whose class still satisfies the condition [Mul13, §5]. Every arrow at a source or a sink is a covering pair, which is what the searches below use.

Mutation-acyclic

A class is mutation-acyclic (equivalently, cluster-acyclic [BBH11]) if some quiver in it is acyclic. Finding an acyclic member proves true directly, and a fully explored class with no acyclic member proves false. For a partially explored class the search alone can only say unknown.

def class_is_mutation_acyclic(members, is_open):
    if any(is_acyclic(m) for m in members):
        return True
    return False if not is_open else None    # closed: proved; open: unknown

An unknown can then be upgraded to a definite false by heredity: a full (induced) subquiver of a mutation-acyclic quiver is mutation-acyclic [War11], so if any member contains an induced subquiver already known not to be mutation-acyclic, the whole class is not mutation-acyclic. The base case is the Markov quiver — rank 3, all |bij| = 2, cyclically oriented — whose mutation class consists of a single quiver up to isomorphism and contains nothing acyclic [BBH11]. Resolving classes in ascending rank lets that propagate upward. Because the census stores connected quivers only, a disconnected subquiver is looked up one component at a time.

# Heredity forces a not-mutation-acyclic (n-1)-subquiver, so deleting a
# single vertex suffices; components are looked up separately.
def has_known_non_ma_subquiver(members, known_false):
    for m in members:
        if len(m) < 4:                       # smallest witness is Markov (rank 3)
            continue
        for k in range(len(m)):              # delete one vertex
            for comp in connected_components(delete_vertex(m, k)):
                if len(comp) >= 3 and known_false.get(quiver_id(comp)) is False:
                    return True
    return False

Banff

The Banff condition is a sufficient criterion for local acyclicity, checked by the Banff algorithm [Mul13, §5]. QMD tests it by recursive source/sink deletion: a quiver passes if it is acyclic, or if it has a vertex k that is a source or a sink, together with a neighbour j, such that deleting k and (separately) deleting j each leave a quiver whose mutation class still satisfies the condition. Every arrow at a source or a sink is a covering pair, so both are tried; the verdict is therefore unchanged if every arrow of the quiver is reversed.

The search runs over the mutation class, so a class passes if any of its members does.

def check_condition(q, kind):           # kind in {"banff", "louise", "p_prime"}
    if is_acyclic(q):
        return True                                 # base case
    for k in sources(q) + sinks(q):                 # extremal vertices, de-duplicated
        if not cond_class(delete_vertex(q, k), kind):
            continue
        if kind == "p_prime":
            return True                             # P': one deletable vertex suffices
        for j in neighbours(k, q):                  # Banff/Louise also need a neighbour j
            if not cond_class(delete_vertex(q, j), kind):
                continue
            if kind == "banff":
                return True
            if cond_class(delete_two(q, k, j), kind):   # Louise also needs Q \ {k, j}
                return True
    return False

def cond_class(q, kind):                # does any quiver in the class satisfy it?
    if is_mutation_acyclic(q):          # acyclic member found: yes, immediately
        return True
    ...                                 # else BFS the class within the search budget

Louise

The Louise property [LS22] strengthens Banff: in addition to deleting the extremal vertex k and a neighbour j, the quiver with both k and j removed must again satisfy the condition (the third branch in the code above). Louise holds for all acyclic cluster algebras and for most cluster algebras from marked surfaces, and it implies local acyclicity.

P′

The P′ condition as recorded here is the weakest of the three deletion criteria: a quiver passes if it is acyclic, or if it has a source or a sink whose deletion leaves a quiver whose class still satisfies P′ — no neighbour condition is required.

Naming caveat. This is the condition supplied to the project by the maintainer, and it is recorded and computed exactly as defined above. It should not be assumed identical to the classes called P and P′ elsewhere in the literature (for instance the class P of Kontsevich–Soibelman and the class P′ of Ladkani, which are defined by closure under triangular extension rather than by vertex deletion, and which are known not to coincide with local acyclicity). We have not identified a published source for the source/sink-deletion condition under this name; treat the definition above as authoritative for this database.

Three-state values & provenance

Several properties are semidecidable, or depend on a search that may be cut short. Every such value is reported with three states, never a guess:

  • Yes (true) — a witness was found and recorded.
  • No (false) — the search was provably exhaustive and no witness exists.
  • Unknown (null) — the search was truncated by a depth limit, a timeout, an arrow-weight cap or the node cap. A null is never a "no".

This applies to Banff, Louise, P′, mutation-acyclicity, per-quiver mutation-finiteness, representation type and planarity. A truncated flag is threaded through the whole search, so a No is only reported when nothing anywhere was cut short.

Each class carries a provenance object recording, per property, the state and the witness that established it — for Banff, Louise and P′ the mutation sequence and the deletion certificate; for a proved-infinite class, the criterion used. The search budget is deliberately generous for classes that can certify and small for those that cannot, and it is not the same for every rank; where the budget was zero the value is simply unknown.

Nicknames

Some classes have a curated name — Markov, for example. Nicknames are editorial, not computed: they live in data/nicknames.json in the repository, each entry naming the class both by id and by a member matrix, so a name survives any regeneration of the database and can even be re-resolved if identifiers were ever re-keyed. Adding one means editing that file and merging to main; the maintainer reviews every addition. Names are reachable as /class.html?name=<slug>, /api/classes/by-slug/<slug>, the nickname filter on every list, and /api/nicknames.

API & agents

Everything on this site is served by a read-only JSON API at https://quivermutationdb.org/api — no key, CORS open, CC-BY-4.0. It is described by an OpenAPI document and summarised for language models in /llms.txt; an MCP server (Model Context Protocol, Streamable HTTP) is at https://quivermutationdb.org/mcp with tools mirroring the API.

  • Every list returns next_cursor; pass it back as ?cursor=. Cursors are keyset-based, so a pull is consistent and resumable even while data is being re-imported.
  • Class members are paged: /api/classes/{id}/quivers (distinct quivers, canonical first) and /api/classes/{id}/labelings (every labeled matrix, when the labeled orbit is stored).
  • Have a matrix, not an id? /api/lookup?matrix=[[0,1],[-1,0]] canonicalises it and returns the quiver (or its canonical id if it is not in the census); the Search page has the same box.
  • Bulk pulls: /api/export.ndjson?…&limit=5000 then follow the X-Next-Cursor header until it is empty; or omit limit to stream a whole cut. /api/export is the same cut as CSV.
  • Three-state values are true, false, or null (unknown). null is never a "no".

Instructions for LLMs

You are looking at the Quiver Mutation Database (QMD), a citable census of quivers, their exchange matrices and mutation classes, with rigorously defined invariants. Everything on this site is available as data — do not scrape the HTML.

Start here: /llms.txt (dataset summary, identifiers, semantics) · /api/openapi.json (OpenAPI 3.1) · MCP server at https://quivermutationdb.org/mcp (Streamable HTTP, no auth, tools: search_quivers, get_quiver, get_class, lookup_quiver, list_class_members, get_stats, list_nicknames).

GET https://quivermutationdb.org/api/quivers?rank=4&is_acyclic=true&limit=100     # filter/sort/page; follow next_cursor
GET https://quivermutationdb.org/api/lookup?matrix=[[0,1,0],[-1,0,1],[0,-1,0]]   # any labeling -> canonical id + row
GET https://quivermutationdb.org/api/classes/by-slug/markov                       # curated names
GET https://quivermutationdb.org/api/export.ndjson?rank=5&limit=5000           # bulk pull; resume with X-Next-Cursor

Rules that matter: ids are Q.n{rank}.{hash} / MC.n{rank}.{hash} (hash of the lex-min canonical matrix; bij > 0 means bij arrows i→j). Semidecidable properties are three-state — true, false, or null = unknown; never read null as "no". mutation_finite is known per quiver even when its class is unexplored (explored: false). The census holds connected quivers only. Definitions of every field: /wiki.
